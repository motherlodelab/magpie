## 2. Tier 1 — build next, in order

### R1. Deterministic selector relocation (heal pass) — *the structural moat*
- **What:** today a broken cached selector trips LLM re-synthesis (cost, latency, key required). Insert a zero-LLM middle step: fingerprint the cached element (tag/text/attrs/parent chain), score candidate nodes on the fresh page, accept above threshold, else fall back to existing LLM heal.
- **Why it wins:** makes "zero-LLM by default" literally true in the one path where it currently isn't; cuts heal cost to zero in the common redesign case; Scrapling proved "self-healing selectors" is a marketable headline — this makes ours strictly stronger (deterministic AND LLM fallback). The 09-20 doc's own verdict: "highest-value cross-pollination in this doc."
- **Cost:** ~1–2 days, pure DOM work in `selector/`, no new deps. Phase name TBD when planned (`stack: go`).

### R2. Execute phase-Z (+Z.5 credential profiles) — *already specced*
- **What:** `plan/phase-Z.md` (~6 h): env-var credentials for GitHub/Reddit OAuth, plus `magpie profile save/ls/rm` + `scrape --as <name>` for any static-credential site. Test plan ready in `plan/phase-Z-tests.md`.
- **Why it wins:** reliability for the two flakiest tokenless verticals; the credential foundation the desktop settings UI will ride; the honest "bring your own credential" answer to the login question (LinkedIn stays out — see `plan/phase-Z.md` §5).
- **Cost:** ~6 h, specced to the test-name level. Execute manually (`run-phase` hard-blocks on `stack: go`).

## 3. Tier 2 — cheap adoption & revenue levers (a day, combined)

### R3. `magpie probe <url>` — capability preview
Print BEFORE scraping: which verticals match (`MatchURL` + `List` already exist), what JSON-LD/schema.org blocks the page carries, whether the JS-escalation heuristic would fire, heal-cache state. This is the demo that sells the desktop app to a non-developer — point at a site, see the typed data you'll get. Nothing in the 09-20 matrix (any vendor) has it. ~half day.

### R4. `magpie schema <vertical>` — JSON Schema export of a vertical's record
The records are hand-written maps; formalize them into published JSON Schema so agents (MCP-first story) and the desktop UI can discover fields before calling. Trivial, matches webclaw/Firecrawl's schema-based UX for free. ~2–3 h.

### R5. Verticals by demand evidence, not by list
The webclaw-derived vertical list is exhausted (27 shipped). Next additions come from what desktop beta users actually point at — candidates in buyer-shaped territory: app-store reviews, G2/Capterra, booking/travel status. Every candidate must pass the anonymous-scrapeability test that killed LinkedIn (`plan/phase-Z.md` §5): anonymous HTTP reachable, structured data or stable DOM, no authwall. Gate on real user evidence.

## 4. Standing say-no list (re-litigate nothing without new evidence)

- REST API daemon (Service layer is ready when wanted; `magpie serve` MCP stays the interface)
- Live-view AI browser interact; stealth-browser tier (CamouAuto-class maintenance swamp)
- `--country` geo targeting (hosted-only value)
- Built-in scheduler/cron daemon — platform owns the clock; `watch --once` + `crawl --resume` + `flock` are the primitives (recipe belongs in README "Scheduling" docs, fold into Z.4)
- Distributed/cluster anything (2026-09-28 ruling); LinkedIn in any form (authwall / OAuth-empty / §4.1 no-storage / SNAP-gated — `plan/phase-Z.md` §5)

## 5. Recommended order

**R1 → R2 → R3 → R4**, with R5 gated on beta evidence. R1 is the only structural-moat item; R2 is specced and unblocks the desktop credential story; R3+R4 are one day combined and both feed the same agent/desktop adoption narrative.
